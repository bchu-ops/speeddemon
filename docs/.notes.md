### 2. Statistical Relationship Equations
#### Covariance
Measures the directional relationship between two random variables $X$ and $Y$.
$$cov(X, Y) = \frac{\sum_{i=1}^{n} (x_i - \bar{x})(y_i - \bar{y})}{n - 1}$$
*   **$\bar{x}, \bar{y}$**: Sample means.
*   **$n$**: Number of data points.

#### Pearson Correlation Coefficient ($\rho$ or $r$)
The standardized measure of the linear relationship between two variables.
$$r = \frac{cov(X, Y)}{s_x s_y}$$
*   **$s_x, s_y$**: Standard deviations of $X$ and $Y$.
*   **Range**: $[-1, 1]$.

#### Covariance Matrix ($\Sigma$)
A matrix where each element $\Sigma_{i,j}$ is the covariance between the $i$-th and $j$-th elements of a random vector.
$$\Sigma = \begin{bmatrix} var(X_1) & cov(X_1, X_2) \\ cov(X_2, X_1) & var(X_2) \end{bmatrix}$$

### 3. Inferential Statistics & Significance
#### Z-Score (Standardization)
Calculates how many standard deviations a data point $x$ is from the mean $\mu$.
$$z = \frac{x - \mu}{\sigma}$$
*   **$\sigma$**: Population standard deviation.

#### Z-Test Statistic
Used to determine if the difference between a sample mean $\bar{x}$ and a population mean $\mu_0$ is significant.
$$Z = \frac{\bar{x} - \mu_0}{\sigma / \sqrt{n}}$$

#### P-Value
The probability $P(Z \ge |z|)$ under the null hypothesis. 
*   **Interpretation:** If $p < \alpha$ (usually $0.05$), we reject the null hypothesis in favor of statistical significance.

## 1. Concepts: Variance & Model Sensitivity

### The Role of Outliers
Variance is designed to be a "risk-sensitive" measure. By quantifying the spread of data, it highlights instability. In production, high variance often indicates a data quality issue or a highly volatile process.

### Robustness vs. Sensitivity
*   **Sensitivity (Variance/L2):** Amplifies large deviations; ideal for detecting sensor glitches or critical failures.
*   **Robustness (MAD/L1):** Resists outliers; ideal for finding the "typical" behavior of a system despite noisy data.

---

## 2. Technical Mechanics: The Pro Data Stack

A senior-grade pipeline leverages **vectorized execution** and **zero-copy memory sharing** to handle the high variance of modern datasets.

### The ELT Workflow
1.  **Extract:** Fetching telemetry (e.g., [FastF1](https://docs.fastf1.dev)) into a local `.cache/`.
2.  **Load (Polars):** High-speed conversion of raw streams to **Bronze Parquet**.

| Method | Penalty Type | Output Effect |
| :--- | :--- | :--- |
| **L2 (Ridge)** | Squared Weights | Shrinks coefficients; keeps all features; stable. |
| **L1 (Lasso)** | Absolute Weights | Forces coefficients to zero; performs **Feature Selection**. |
| **Elastic Net** | Combined | Balances stability and sparsity. |

## 3. Mathematical Proofs & Equations

### Variance (Population)
The sensitivity to outliers is derived from the squaring of deviations.
$$\sigma^2 = \frac{\sum_{i=1}^{N} (x_i - \mu)^2}{N}$$

**Variables:**
*   $\sigma^2$: Variance
*   $x_i$: The $i^{th}$ data point
*   $\mu$: Population Mean
*   $N$: Total number of observations

### Differentiability & Gradient Descent
We prefer squared loss ($L$) over absolute loss because the derivative of the squared term is continuous, allowing for **Stochastic Gradient Descent (SGD)**.

**Squared Loss Derivative:**
$$\frac{d}{dw} (y - wx)^2 = -2x(y - wx)$$
*Result: A smooth slope that guides the model to the minimum.*

**Absolute Loss Derivative:**
$$\frac{d}{dw} |y - wx| = -x \cdot \text{sgn}(y - wx)$$
*Result: Undefined at zero (the "sharp corner"), making optimization mathematically "jagged."*

### Regularized Cost Functions
**Ridge (L2) Penalty:**
$$J(w) = \text{MSE} + \lambda \sum_{j=1}^{p} w_j^2$$

**Lasso (L1) Penalty:**
$$J(w) = \text{MSE} + \lambda \sum_{j=1}^{p} |w_j|$$

# High-Performance ELT Implementation (Data Engineering Path)

In a senior data engineering workflow, we prioritize **Idempotency** and **Vectorized Operations**. We load raw high-frequency sensor logs into a "Bronze" layer and use the **Pro Data Stack** (DuckDB + Polars) to perform "Zero-Copy" transformations for dead reckoning and feature engineering.

```python
import polars as pl
import duckdb
import numpy as np

# 1. EXTRACT & LOAD (Bronze Layer)
# Using Polars for blazing fast I/O of high-frequency telemetry
# In production, this would be a Parquet file from an S3 bucket
raw_data = pl.DataFrame({
    "ts": np.arange(0, 10, 0.01),  # 100Hz timestamps
    "gyro_x": np.random.normal(0, 0.1, 1000),
    "gyro_y": np.random.normal(0, 0.1, 1000),
    "gyro_z": np.random.normal(0.5, 0.05, 1000) # Constant slow rotation
})

# Connection to an analytical database (DuckDB)
con = duckdb.connect(database=':memory:')
con.register("raw_telemetry", raw_data)

# 2. TRANSFORM (Silver/Gold Layer)
# Using SQL for Idempotent Dead Reckoning and Structural Feature Engineering
transformation_query = """
CREATE OR REPLACE TABLE processed_motion AS
WITH Calibration AS (
    -- Calculate static bias (drift) from the first 50 samples
    SELECT AVG(gyro_z) as z_bias FROM raw_telemetry LIMIT 50
)
SELECT 
    ts,
    gyro_z,
    -- DEAD RECKONING: Integration of velocity to Heading (Degrees)
    -- Formula: Σ(velocity - bias) * dt
    SUM(gyro_z - (SELECT z_bias FROM Calibration)) 
        OVER (ORDER BY ts) * 0.01 AS absolute_heading,
    
    -- FEATURE ENGINEERING: 10-sample Rolling Variance (L2 Norm)
    -- Used to detect 'jitter' or 'stability' signatures
    VARIANCE(gyro_z) OVER (
        ORDER BY ts ROWS BETWEEN 9 PRECEDING AND CURRENT ROW
    ) AS z_variance_l2,
    
    -- FEATURE ENGINEERING: Signal Magnitude Area (SMA)
    -- Intensity of movement across all axes
    (ABS(gyro_x) + ABS(gyro_y) + ABS(gyro_z)) AS motion_intensity
FROM raw_telemetry;
"""

con.execute(transformation_query)

# 3. OUTPUT FOR ML
# The "Zero-Copy" handoff to a Data Science environment
final_df = con.table("processed_motion").pl()
print(final_df.tail(5))
```
